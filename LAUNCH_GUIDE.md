# 🐘 Supabase Setup Guide — Super Easy Version

Hi! This guide helps you set up **Supabase**, a free service that remembers
your photos and booking requests forever, so everyone who visits your website
can see them — not just you on your own computer.

**Why Supabase?** Unlike some other free options, Supabase never asks for a
credit card, ever — even the file storage part is 100% free with no billing
account required. That's why we're using it. 🎉

We'll go slow, one click at a time. Ready? Let's go! 🚀

---

## 🧸 Part 1: Make a Supabase Project

Think of a "project" like a toy box that holds all your website's photos and
information.

1. Open a new tab and go to **supabase.com**
2. Click **Start your project** (or **Sign up**) — free, no credit card needed
3. Sign up with an email or a GitHub account
4. Click **New Project**
5. Type any name you like, for example: `ravenscraft-visuals`
6. Type any database password (you won't need to remember it for anything below)
7. Pick any region close to you
8. Click **Create new project**
9. Wait about a minute while it builds your toy box 🧰

🎉 You just made your project!

---

## 📜 Part 2: Run the Setup Script

This one script creates everything your site needs: a place for your
bookings, a place for your photo info, and a place for the actual photo
files.

1. On the left side menu, click **SQL Editor**
2. Click **New query**
3. Copy this whole box below:

```sql
-- 1) Storage bucket that holds the actual image files
insert into storage.buckets (id, name, public)
values ('ravenscraft-media', 'ravenscraft-media', true)
on conflict (id) do update set public = true;

-- 2) Table for the logo, About-section photo, and portfolio images
create table if not exists public.site_assets (
  id uuid primary key default gen_random_uuid(),
  kind text not null check (kind in ('logo', 'about', 'portfolio')),
  path text not null unique,
  name text,
  alt text,
  sort_order integer not null default 0,
  created_at timestamptz not null default now()
);

-- 3) Table for booking requests submitted from the website
create table if not exists public.bookings (
  id integer generated by default as identity primary key,
  name varchar(120) not null,
  email varchar(200) not null,
  phone varchar(40),
  category varchar(80) not null,
  package_interest varchar(160),
  preferred_date varchar(40),
  location varchar(180),
  message text,
  status varchar(30) not null default 'new',
  created_at timestamptz not null default now()
);

alter table public.site_assets enable row level security;
alter table public.bookings enable row level security;

drop policy if exists "Public can view site assets" on public.site_assets;
create policy "Public can view site assets"
on public.site_assets for select
to anon, authenticated
using (true);

drop policy if exists "Authenticated admins manage site assets" on public.site_assets;
create policy "Authenticated admins manage site assets"
on public.site_assets for all
to authenticated
using (true)
with check (true);

drop policy if exists "Anyone can submit bookings" on public.bookings;
create policy "Anyone can submit bookings"
on public.bookings for insert
to anon, authenticated
with check (true);

drop policy if exists "Authenticated admins view bookings" on public.bookings;
create policy "Authenticated admins view bookings"
on public.bookings for select
to authenticated
using (true);

drop policy if exists "Authenticated admins update bookings" on public.bookings;
create policy "Authenticated admins update bookings"
on public.bookings for update
to authenticated
using (true)
with check (true);

drop policy if exists "Public can read Ravenscraft media" on storage.objects;
create policy "Public can read Ravenscraft media"
on storage.objects for select
to anon, authenticated
using (bucket_id = 'ravenscraft-media');

drop policy if exists "Authenticated admins upload Ravenscraft media" on storage.objects;
create policy "Authenticated admins upload Ravenscraft media"
on storage.objects for insert
to authenticated
with check (bucket_id = 'ravenscraft-media');

drop policy if exists "Authenticated admins update Ravenscraft media" on storage.objects;
create policy "Authenticated admins update Ravenscraft media"
on storage.objects for update
to authenticated
using (bucket_id = 'ravenscraft-media')
with check (bucket_id = 'ravenscraft-media');

drop policy if exists "Authenticated admins delete Ravenscraft media" on storage.objects;
create policy "Authenticated admins delete Ravenscraft media"
on storage.objects for delete
to authenticated
using (bucket_id = 'ravenscraft-media');
```

4. Paste it into the box on the screen
5. Click **Run** (bottom right)
6. You should see a green "Success. No rows returned." message

🎉 Your toy box now has shelves for photos and bookings!

## 🙋 Part 3: Make Your Own Login

This is the email and password that only YOU will use to add photos.

1. On the left side menu, click **Authentication**
2. Click the **Users** tab
3. Click **Add user** → **Create new user**
4. Type any email (it doesn't have to be real — just something you'll remember)
5. Type any password you'll remember
6. Turn ON the switch that says **Auto Confirm User**
7. Click **Create user**

Remember this email and password — you'll use it to log into your website
later! ✍️

---

## 📦 Part 4: Get Your Special Codes

These two little codes tell your website which toy box (project) belongs to
it.

1. Click **Settings** at the bottom of the left menu → **API Keys**
2. You'll see two things you need:
   - **Project URL** — click **General** in that same Settings menu to find it (looks like `https://xxxxxxxxxxxx.supabase.co`)
   - **Publishable key** — under "Publishable key" on the API Keys page, a
     jumble of letters starting with `sb_publishable_...` (this is the same
     thing as an "anon public" key — just a newer name for it)
3. Click the little copy icon 📋 next to each one, and paste them somewhere
   safe like Notepad — you'll need both in the next step

> 💡 Is it safe to share this key? Yes! It's specially made to be public —
> that's why it says "Publishable keys can be safely shared publicly" right
> on the page. The real protection is the script you ran in Part 2, not this
> key.

## 🖥️ Part 5: Tell Your Website About Supabase

1. Go back to your website and open the **Admin** page
2. You'll see a **"Connect Your Database"** screen
3. Copy your **Project URL** from Part 4 and paste it in the first box
4. Copy your **Publishable key** from Part 4 and paste it in the second box
5. Click the button **🔎 Test Connection**
   - If it says ✅ **Connected!** — hooray, you did it!
   - If it shows a red message, read what it says — it usually means the
     script from Part 2 needs to be run again
6. Click **Save & Continue**
7. Log in with the email and password you made in Part 3
8. Try uploading a test photo to make sure everything works! 📸

## 🌍 Part 6: Make It Work for EVERYONE (the last step!)

Right now, your photos only show up on **your own computer/browser**. To make
them show up for **every visitor**, on every phone and computer:

👉 **Copy your Project URL and Publishable key again** (from Part 4) and
**paste them back to me in the chat.**

I'll build them permanently into your website's code so every visitor
automatically sees your real photos and logo — no extra steps needed from you
or from them. Then just publish your site like normal!

## 💤 One Thing to Know: The "Sleepy Project" Rule

Supabase's free plan is completely free forever, but if your project doesn't
get any visits for **7 days in a row**, it takes a little nap 😴 to save
resources.

**If that happens:** just go to **supabase.com**, log in, open your project,
and click **Resume project**. It takes about 10 seconds, nothing is lost, and
there's no charge — ever. If your site gets regular visitors or you check
Admin now and then, this basically never happens.

### 🆘 If something goes wrong

- **Red error when testing connection?** Read the message — it usually tells
  you exactly what's missing (like forgetting to run the script in Part 2).
- **Can't log in?** Double check the email and password match exactly what
  you typed in Part 3 (no extra spaces!), and make sure Auto Confirm was ON.
- **Site looks empty after a week away?** That's just the sleepy project
  rule above — log in to supabase.com and click Resume project.
- **Still stuck?** Just tell me what the error message says, and I'll help
  you fix it right away.
